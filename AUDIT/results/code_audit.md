# Code audit — NEWSLAM slam3_pytorch.py (Mac, 715 lines) — line references to that file

## REAL implementations (verified by reading + tests)
- **RoPE** (L109-145): correct formulation — inv_freq = 10000^(-2i/d), even/odd rotation applied to Q and K. Tests: norm preservation PASS, relative-position property PASS.
- **SparseTopK MoE FFN routing** (L285-360): gate → top-k=2 of 4, softmax over selected logits, weights sum to 1 (test PASS). Load-balancing loss is the genuine Switch-Transformer form N·Σ(freq·importance) (L300-320); finite, and reducible by training the gate (test PASS).
- **EF segment structure**: sequence split into 4 segments, each processed by a different EFBlock, at 4 rotations (roll shifts), fused by a learned per-token gate (L438-530). This part does what its comments say.
- **Specialization loss**: KL(target_profile ‖ softmax(frequency_analyzer output)) — a real, differentiable loss (L383-397).

## FINDINGS (would matter in a research interview)
1. **"MoE Attention" has no MoE in it.** `MoEAttentionModule` builds a router `self.gate = nn.Linear(...)` at **L189** and NEVER calls it — the only `.gate(` call in the file is the FFN's (L315). Attention is plain multi-head attention. Test `test_moe_attention_gate_gets_gradients` FAILS: gate grad is None. Every claim of "MoE attention" is false for this file; only the FFN is MoE.
2. **The MoE FFN is not sparse in compute.** `SparseTopKMoEFFN.forward` (L342-356) runs `self.experts[expert_idx](x)` on the FULL [B,T,D] tensor for every expert, then zeroes out unselected tokens by weight multiplication. FLOPs = dense 4-expert FFN. Test `test_moe_ffn_actually_sparse_compute` FAILS (hooks: every expert saw all 32/32 tokens). On hardware this costs ~4× a dense FFN of hidden 256 while only 2 experts' outputs are used per token.
3. **Causality is broken — the model can see the future.** Level-1 K/V are computed from the FULL input sequence and handed to every EF block, whose attention (L256-263) applies NO mask when Q length ≠ K/V length ("pass # No masking when using cached K/V"). Segment queries therefore attend to K/V derived from tokens in later segments. Test `test_model_is_causal` FAILS: perturbing tokens 96-127 changed logits at positions 0-31 by up to **0.1208**. Any perplexity from this architecture as an LM is optimistically contaminated.
4. **The "KV cache" is not an inference KV cache.** It is computed once, in one shot, from the Level-1 input embeddings (before any contextual processing), then transplanted into *different modules'* attention (EF blocks consume K/V produced by Level-1's k_proj/v_proj as if they were their own). There is no incremental/autoregressive decoding path in the file at all. The honest name is "cross-layer K/V sharing from layer 1", and finding 3 is its price.
5. **RoPE position mismatch in EF blocks.** Cached K carries GLOBAL positions (0-127); each segment's Q is rotated with LOCAL positions (0-31) because apply_rope restarts at the segment. For segments 2-4, Q-K relative offsets are wrong by the segment's start offset.
6. **"Entropy early exit" is not entropy.** `compute_entropy` (encoder) = mean(|Linear(x − prev_x)|) — the mean absolute value of a learned projection of the residual change, compared to threshold 0.1. Nothing computes an entropy. The mechanism (stop EF cycles when the residual stops changing) is a reasonable idea wearing a wrong name; the threshold is unvalidated and, with MAX_EF_CYCLES=2, it can only ever skip at most one cycle, only in inference, only after cycle 1.
7. **"Frequency profiles / specialization" is naming, not analysis.** `frequency_analyzer` is a Linear(128→4) on hidden states; no frequency transform (FFT/band analysis) exists anywhere. The targets ([1,.5,.2,.1] "Structure", etc.) are hand-invented vectors, and the KL loss forces a learned linear probe to output them. Whether blocks "specialize" in anything measurable is never tested in the repo.
8. **No training loop exists in the model file.** No optimizer, no backward, no schedule — `__main__` only runs a forward pass. All training lived in Kaggle/Colab notebooks (`train_kaggle.ipynb`, `train_wikitext103_optimized.ipynb`) whose saved copies have **no executed outputs** (per prior inspection) and whose "PPL at 50K steps: 30-40" line is a markdown *expectation*, not a result. Config values (LEARNING_RATE, MAX_STEPS=50,000, WARMUP_STEPS) are declared but never consumed by any code in the file.
9. **Model `forward(src, training=True)` defaults to training=True independent of `model.eval()`** — callers who forget the flag get loss-collection and (via FFN) gating noise behaviour in "inference". A footgun, and it makes the repo's own `inference.py` behaviour depend on a nonstandard convention.
10. **Dead / vestigial code**: `MetricsTracker` value stats unused by any training code in-file; `Level1Attention` is a wrapper used for both "Level 1" and "Level 3" (level3_attn is a second Level1Attention — fine, but the naming inflates the architecture diagram); each EFBlock's specialization_proj + the unused attention gates add parameters that do nothing (attention gates alone: 10 modules × 516 params of pure dead weight — small, but symptomatic).
11. **Parameter reality**: 15.84M total, of which embedding 6.43M + output head 6.48M = **81.6%**. The entire "architecture" (EF cycles + both attention levels) is ~2.92M params. Any comparison must be read with that in mind.
12. **What is NOT here**: no custom tokenizer (GPT2TokenizerFast, vocab 50,257 — the v1 BERT tokenizer didn't carry over), no FlashAttention (config flag False, and no implementation), gradient checkpointing flag declared (CHECKPOINT_GRADIENTS=True) but never applied in the model file.
